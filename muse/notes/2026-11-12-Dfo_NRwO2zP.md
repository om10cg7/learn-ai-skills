## 要約

単一画像のインフォグラフィック『Claude Code Project Structure（November 2026 Edition）』（内容は画像を目視で確認）。Claude Code のプロジェクトに置く設定ファイル群をツリー図で整理する。ルート: CLAUDE.md（セッション開始時に読み込まれる。プロジェクト概要・技術スタック・コマンド・コーディング規約を200行以内に保つ。CLAUDE.local.md で上書き可）、CLAUDE.local.md、AGENTS.md（CLAUDE.md が無いときに読まれる。Codex／Cursor／Copilot と共通のファイルで、CLAUDE.md から import すれば両立できる）、.mcp.json（MCP 連携設定。GitHub／JIRA／Slack／DB 等に接続し、git でチーム共有）。.claude/ 配下: settings.json（権限とツールアクセスを制御。モデル・hooks・sandbox・plugins・env を持ち、settings.local.json で上書き可）と settings.local.json、rules/（トピック別のモジュール式 .md で code-style／testing／api-conventions。frontmatter で適用パスを絞る）、skills/（タスクの文脈で自動発火し、必要なときだけ読み込まれる。スラッシュコマンドにもなる。例は deploy/）、agents/（役割特化のサブエージェント。独立した文脈ウィンドウと独自のツール・モデル・git worktree を持つ。例は code-reviewer／security-auditor）、hooks/（イベント駆動スクリプト。検証・lint・整形の自動化と危険な操作のブロック。例は validate-bash.sh）、worktrees/（.gitignore へ追加）。キャプションの主張は『長いプロンプトよりセットアップが大事』で、実践として CLAUDE.md を短く保つ／複雑な編集の前に計画する／繰り返し作業をスキル化する／ガードレールに hooks を使う、の4つを挙げる。『30+ hook events』等の数値は画像内表記ママで裏取りなし。

AI に書かせた日本語は、読み返すと「どこか不自然」と感じることがあります。「時間を溶かす」「静かに壊れる」といった比喩や、太字と箇条書きの多用が原因です。直す作業は、自分でやると意外に時間がかかります。

この記事では、AI の文章を推敲するスキル「yomiyasu（よみやす）」を Claude Code に入れ、AI らしい文章を直させるところまでをまとめます。インストールの前に、安全性も自分で確認しました。

## 🤔 なぜ yomiyasu を試したいか

note の記事は、Claude Code に手伝ってもらいながら書いています。下書きはそれなりに整うのですが、比喩の言い回しや、見出しに付く絵文字など、AI の癖が残ります。

その癖を、毎回自分で探して直しています。直す基準をスキルとして Claude Code に持たせられれば、推敲の手間が減るはずです。

前回までは、Claude Code に NotebookLM や株価のツールをつなぐ記事を書きました。今回は、文章を直す側のスキルです。

## 🛠 yomiyasu とは？

GitHub で公開されている、AI が書いた日本語を直すためのスキルです。作者は nanaism、ライセンスは MIT で、バージョンは 1.0.7 でした。

Claude Code のほか、Cursor や Codex などでも使えます。「この文章を読みやすくして」と頼むと、スキルの手順書（SKILL.md）に沿って、Claude が書き直します。

**直す内容**
- 「時間を溶かす」「静かに壊れる」などの比喩動詞を、ふだんの言葉に直す
- 「ツールが語る」のような擬人化を、客観的な言い方に直す
- 太字、箇条書き、絵文字、ダッシュ記号を減らす
- 主語と目的語、文末の働きをそろえる。意味は変えない

**ドメイン（文章の種類）は3つ**
- tech：技術記事
- business：仕様書、提案書、PR の説明文
- essay：エッセイ、個人の発信

**同梱のスクリプトは2つ**
- yomiyasu_lint.py：AI らしい書き方を検出して、100点満点で採点する
- yomiyasu_diff.py：書き直しの前後を比べて、意味の増減や文末の変化を挙げる

2026年10月時点の README に基づきます。

## 🚀 導入手順

### 環境

- OS：Windows 11 Pro
- Claude Code：2.1.251
- Node.js：v24.18.0（npm 11.16.0）
- skills（npx で動かす導入ツール）：1.7.0
- Python：3.11.9（同梱スクリプトの実行用）

### 1. スキルを入れる

README が推奨する方法は `npx skills add` です。今回は、作業フォルダの中だけに入れたかったので、次のオプションを付けました。

```powershell
npx skills add nanaism/yomiyasu -a claude-code -y --copy
```

`-a claude-code` で Claude Code 向けに限定し、`--copy` でファイルを複製しています。`-g` を付けないので、ユーザー全体ではなく、このフォルダだけに入ります。

実行すると、.claude\skills\yomiyasu にスキルが入りました。作業フォルダには skills-lock.json も作られ、取得元（nanaism/yomiyasu）とハッシュが記録されます。

### 2. 入れたものを確認する

スキルは「指示文とスクリプトの集まり」なので、入れる前後に中身を見ておくのが安全です。確認できたことは次の通りです。

- インストール時の評価は、Gen が Safe、Socket が 0 alerts、Snyk が Low Risk
- 普段使うスクリプト2つは、標準ライブラリだけで動く。通信もサブプロセスの起動もない
- ほかに実行ファイル（.sh、.ps1、.exe、.js）はない
- 通信先として書かれているのは、GitHub の URL だけ

唯一の例外が build_corpus.py です。`claude -p` を呼びますが、検証用データを作る開発者向けで、普段は動きません。

全ファイルを読んだわけではありません。SKILL.md は236行、約4.4万字あり、冒頭と手順の部分を読みました。

### 3. 使い方

Claude Code に、次のように頼みます。

> ドメイン tech。work/before.md の文章を読みやすくして。結果は work/after_skill.md に保存して。

ドメインは、「技術記事向けに」のような言い方でも指定できます。

## ⚠️ ハマったところ

### スクリプトの日本語が文字化けする

yomiyasu_lint.py の --help を実行すると、日本語が読めない文字で表示されました。Windows のコンソールの文字コード（cp932）と、スクリプトの出力が合っていません。

環境変数 PYTHONUTF8 を設定すると、直りました。

```powershell
$env:PYTHONUTF8 = "1"
```

### 入れた直後は、スキルが呼べなかった

インストールを終えた時点では、このセッションの一覧にスキルが出ていませんでした。しばらくして別の依頼をした時点で、一覧に出ていました。再起動はしていません。読み込まれた正確なタイミングは確認していません。

### 呼び出さずに書き直すと、結果が変わる

スキルが呼べるようになる前に、Claude Code が SKILL.md を読んで、手で書き直したことがあります。出来上がりは、スキルを呼んだ場合と違いました。

手で書いた版は、箇条書きを地の文にしました。スキル版は、規則どおり箇条書きを残しました。スキルには「箇条書きを地の文にすると同じ文末が3つ以上続くときは、箇条書きのまま残す」という規則があるためです。

### スキルは「自動で直すプログラム」ではない

呼び出すと読み込まれるのは、手順書です。書き直すのは Claude 自身で、スキルは指示書の役目を果たします。lint や diff のスクリプトは、書き直したあとの点検に使います。

## 💻 AI らしい文章を直してみる

### 試す文章

AI らしい書き方を詰め込んだ文章を用意しました。NotebookLM を Claude Code から呼ぶ魅力を紹介する、約400字です。Claude に書かせたものではなく、AI の癖（比喩、擬人化、太字、絵文字、ダッシュ記号）を、意図して入れています。

```markdown
## 🚀 NotebookLMをClaude Codeから呼び出す魅力

NotebookLMに溜め込んだ資料は、使われないまま静かに眠ってしまいがちです。**重要なのは、資料を「ためる」ことではなく「引き出す」こと**です。notebooklm-mcp-cliを導入すれば、Claude Codeがブラウザを開く手間を溶かしてくれます。

### ✨ 3つのポイント

- **ログインの壁**：Windowsでは認証が静かに壊れることがあり、Cookieが1個しか取れません
- **MCPが橋渡しする**：53個のツールがClaude Codeとノートブックをつなぎ、情報の流れを加速させます
- **要約が語りかける**：ノートが自らの中身を物語り、数十秒で結果を返してくれます

このツールは単なるCLIではなく、あなたの知識基盤を支える強力なパートナーです。ツールの真価は導入後に発揮されます——まずは小さく試してみましょう。
```

### 直す前に採点する

yomiyasu_lint.py の結果は、71点でした。指摘は7件（警告5件、参考2件）です。

- 太字が、1,000字あたり10個（推奨は2個以下）
- 箇条書きが、全体の42.9%（推奨は15%以下）
- 絵文字が2か所
- 「静かに壊れる」が、不自然な比喩動詞として検出された
- 「AではなくB」の構文が2か所（参考）

### スキルを呼んで直す

指示は、次の通りです。

> ドメイン tech。work/before.md の文章を読みやすくして。結果は work/after_skill.md に保存して。

出力は次の通りです。

```markdown
## NotebookLMをClaude Codeから呼び出す魅力

NotebookLMにためた資料は、気づかないうちに使われなくなりがちです。重要なのは、資料をためることではなく、引き出して使うことです。notebooklm-mcp-cliを導入すれば、ブラウザを開く手間をClaude Codeが省いてくれます。

### 3つのポイント

- ログインの壁：Windowsでは認証が気づかないうちにおかしくなることがあり、Cookieが1個しか取れません
- MCPでつなぐ：53個のツールがClaude Codeとノートブックをつなぎ、情報のやり取りが速くなります
- 要約の速さ：ノートの要約が数十秒で返ってきます

このツールは単なるCLIではなく、知識基盤を支える存在です。ツールの真価は導入後に発揮されます。まずは小さく試してみましょう。
```

直ったところは次の通りです。

- 「静かに眠る」「静かに壊れる」は、「気づかないうちに」になった。「静かに」が持つ「気づけない」という含みは残している
- 「溶かす」「加速」「語りかける」「物語り」は、ふだんの言い方になった
- 絵文字、太字、ダッシュ記号が消えた
- 「重要なのは〜ではなく〜」は、否定に意味があるため、残った

### 直した後を採点する

yomiyasu_lint.py の結果は、91点でした。指摘は3件（警告1件、参考2件）です。

警告の1件は、箇条書き42.9%です。スキルが規則どおり箇条書きを残したため、この警告は残りました。参考の2件は、残した「AではなくB」です。

太字は、1,000字あたり10個から0個になりました。

### diff で、意味の抜けを確認する

yomiyasu_diff.py で、書き直しの前後を比べました。最初の出力では、「消えた語」に「要約」が入っていました。3つ目の箇条書きの見出しを「返答の速さ」と直したときに、元の「要約」が落ちていたためです。

この箇所を「要約の速さ：ノートの要約が数十秒で返ってきます」に直して、再度比べると、「要約」は消えた語から外れました。スキルの手順にある「修正は1回だけ」に従い、直したのはここだけです。

diff がなければ、見落としていた抜けでした。

### 残った課題

- 「強力なパートナー」が「存在」に変わり、元の評価が弱くなった。diff では、元にない語として「存在」が挙がった
- 試したのは1つの文章だけ。tech 以外のドメイン（business、essay）は試していない
- 採点は yomiyasu 自身のルールによるもので、読みやすさを第三者が評価したわけではない

- インストールは `npx skills add nanaism/yomiyasu -a claude-code -y --copy` の1コマンド。作業フォルダの .claude\skills に入る
- 入れる前に確認した範囲では、スクリプトは標準ライブラリだけで、通信はなかった

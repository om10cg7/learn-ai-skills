3. ハッシュタグ

#ClaudeCode #生成AI #AI活用 #文章術 #AgentSkills

AIに書かせた日本語は、読み返すと不自然に感じることがあります。「時間を溶かす」「静かに壊れる」といった比喩や、太字と箇条書きの多用が原因です。直す作業は、自分でやると意外に時間がかかります。

この記事では、AIの文章を推敲するスキル「yomiyasu（よみやす）」をClaude Codeに入れ、AIらしい文章を直させるところまでをまとめます。インストールの前に、安全性も自分で確認しました。

なぜyomiyasuを試したいか

noteの記事は、Claude Codeに手伝ってもらいながら書いています。下書きはそれなりに整うのですが、比喩の言い回しや見出しに付く絵文字など、AIの癖が残ります。

その癖は、毎回自分で探して直すのが現状です。直す基準をスキルとしてClaude Codeに持たせられれば、推敲の手間が減るはずです。

前回は、Claude Codeで日本株の株価を取得するMCPを試しました。今回は、文章を直す側のスキルです。

yomiyasuとは？

GitHubで公開されている、AIが書いた日本語を直すためのスキルです。作者はnanaism、ライセンスはMITで、バージョンは1.0.7でした。

READMEによると、Claude Codeのほか、CursorやCodexなどでも使えます（私が試したのはClaude Codeだけです）。「この文章を読みやすくして」と頼むと、スキルの手順書（SKILL.md）に沿って、Claudeが書き直します。

直す対象は主に4つです。「時間を溶かす」「静かに壊れる」などの比喩動詞はふだんの言葉に、「ツールが語る」のような擬人化は客観的な言い方に直します。太字、箇条書き、絵文字、ダッシュ記号は減らします。主語と目的語、文末の働きはそろえますが、意味は変えません。

文章の種類（ドメイン）は3つあります。techは技術記事、businessは仕様書、提案書、PRの説明文、essayはエッセイや個人の発信向けです。

同梱のスクリプトは2つです。yomiyasu_lint.pyはAIらしい書き方を検出して100点満点で採点し、yomiyasu_diff.pyは書き直しの前後を比べて、意味の増減や文末の変化を挙げます。

2026年10月時点のREADMEに基づきます。

導入手順

環境

  • OS：Windows 11 Pro
  • Claude Code：2.1.251
  • Node.js：v24.18.0（npm 11.16.0）
  • skills（npxで動かす導入ツール）：1.7.0
  • Python：3.11.9（同梱スクリプトの実行用）

1. スキルを入れる

READMEが推奨する方法は npx skills add です。今回は作業フォルダの中だけに入れたかったので、次のオプションを付けました。

npx skills add nanaism/yomiyasu -a claude-code -y --copy

-a claude-code でClaude Code向けに限定し、--copy でファイルを複製しています。-g は付けていないので、ユーザー全体ではなく、このフォルダだけに入ります。

実行すると、.claude\skills\yomiyasu にスキルが入りました。作業フォルダにはskills-lock.jsonも作られ、取得元（nanaism/yomiyasu）とハッシュが記録されます。

2. 入れたものを確認する

スキルは「指示文とスクリプトの集まり」なので、中身を見ておくと安心です。確認できたことは次の通りです。

  • インストール時の評価は、GenがSafe、Socketが0 alerts、SnykがLow Risk
  • 普段使うスクリプト2つは、標準ライブラリだけで動く。通信もサブプロセスの起動もない
  • ほかに実行ファイル（.sh、.ps1、.exe、.js）はない
  • スクリプトに通信処理はなく、READMEなどにあるのは外部サイトへのリンクだけ

唯一の例外は build_corpus.py で、claude -p を呼びます。検証用データを作る開発者向けで、普段は動きません。

全ファイルを読んだわけではありません。SKILL.mdは236行、約4.4万字あり、冒頭と手順の部分を読みました。

3. 使い方

Claude Codeに、次のように頼みます。

ドメイン tech。work/before.md の文章を読みやすくして。結果は work/after_skill.md に保存して。

ドメインは、「技術記事向けに」のような言い方でも指定できます。

ハマったところ

スクリプトの日本語が文字化けする

yomiyasu_lint.pyのヘルプ表示（--help）で、日本語が読めない文字になりました。Windowsのコンソールの文字コード（cp932とみられます）と、スクリプトの出力が合っていないようです。

環境変数PYTHONUTF8を設定すると、直りました。

$env:PYTHONUTF8 = "1"

入れた直後は、スキルが呼べなかった

インストールを終えた時点では、このセッションの一覧にスキルが出ていませんでした。しばらくして別の依頼をした時点で、一覧に出ていました。再起動はしていません。読み込まれた正確なタイミングは確認していません。

呼び出さずに書き直すと、結果が変わる

スキルが呼べるようになる前に、Claude CodeがSKILL.mdを読んで手で書き直したことがあります。出来上がりは、スキルを呼んだ場合と違いました。

手で書いた版は箇条書きを地の文にしたのに対し、スキル版は規則どおり箇条書きを残しました。これは、スキルに「箇条書きを地の文にすると同じ文末が3つ以上続くときは、箇条書きのまま残す」という規則があるためです。

スキルは「自動で直すプログラム」ではない

呼び出すと読み込まれるのは、手順書です。書き直すのはClaude自身で、スキルは指示書の役目を果たします。lintとdiffのスクリプトは、書き直したあとの点検に使います。

試す文章

## 🚀 NotebookLMをClaude Codeから呼び出す魅力

NotebookLMに溜め込んだ資料は、使われないまま静かに眠ってしまいがちです。**重要なのは、資料を「ためる」ことではなく「引き出す」こと**です。notebooklm-mcp-cliを導入すれば、Claude Codeがブラウザを開く手間を溶かしてくれます。

### ✨ 3つのポイント

- **ログインの壁**：Windowsでは認証が静かに壊れることがあり、Cookieが1個しか取れません
- **MCPが橋渡しする**：53個のツールがClaude Codeとノートブックをつなぎ、情報の流れを加速させます
- **要約が語りかける**：ノートが自らの中身を物語り、数十秒で結果を返してくれます

このツールは単なるCLIではなく、あなたの知識基盤を支える強力なパートナーです。ツールの真価は導入後に発揮されます——まずは小さく試してみましょう。

直す前に採点する

yomiyasu_lint.pyの結果は、71点でした。指摘は7件（警告5件、参考2件）です。

  • 太字が、1,000字あたり10個（推奨は2個以下）
  • 箇条書きが、全体の42.9%（推奨は15%以下）
  • 絵文字が2か所
  • 「静かに壊れる」が、不自然な比喩動詞として検出された
  • 「AではなくB」の構文が2か所（参考）

## NotebookLMをClaude Codeから呼び出す魅力

NotebookLMにためた資料は、気づかないうちに使われなくなりがちです。重要なのは、資料をためることではなく、引き出して使うことです。notebooklm-mcp-cliを導入すれば、ブラウザを開く手間をClaude Codeが省いてくれます。

### 3つのポイント

- ログインの壁：Windowsでは認証が気づかないうちにおかしくなることがあり、Cookieが1個しか取れません
- MCPでつなぐ：53個のツールがClaude Codeとノートブックをつなぎ、情報のやり取りが速くなります
- 要約の速さ：ノートの要約が数十秒で返ってきます

このツールは単なるCLIではなく、知識基盤を支える存在です。ツールの真価は導入後に発揮されます。まずは小さく試してみましょう。

直ったところは次の通りです。

  • 「静かに眠る」「静かに壊れる」は「気づかないうちに」になった。「静かに」が持つ「気づけない」という含みは残している
  • 「溶かす」「加速」「語りかける」「物語り」は、ふだんの言い方になった
  • 絵文字、太字、ダッシュ記号が消えた
  • 「重要なのは〜ではなく〜」は、否定に意味があるため残った

直した後を採点する

yomiyasu_lint.pyの結果は、91点でした。指摘は3件（警告1件、参考2件）です。太字は、1,000字あたり10個から0個になりました。

警告の1件は、箇条書き42.9%です。スキルが規則どおり箇条書きを残したため、この警告は消えませんでした。参考の2件は、残した「AではなくB」です。

diffで、意味の抜けを確認する

yomiyasu_diff.pyで、書き直しの前後を比べました。最初の出力では、「消えた語」に「要約」が入っていました。3つ目の箇条書きの見出しを「返答の速さ」と直したときに、元の「要約」が落ちていたためです。

この箇所を「要約の速さ：ノートの要約が数十秒で返ってきます」に直して再度比べると、「要約」は消えた語から外れました。スキルの手順にある「修正は1回だけ」に従い、直したのはここだけです。diffがなければ、見落としていた抜けでした。

残った課題

  • 「強力なパートナー」が「存在」に変わり、元の評価が弱くなった。diffでは、元にない語として「存在」が挙がった
  • 試したのは1つの文章だけで、tech以外のドメイン（business、essay）は試していない
  • 採点はyomiyasu自身のルールによるもので、読みやすさを第三者が評価したわけではない

この記事にも使ってみた

この記事の下書きにも、同じスキルを使いました。試しに載せたサンプル文を除いて測ると、下書きのlintは0点で、指摘は34件でした。見出しの絵文字、英単語の前後の半角空白、同じ文末の連続、箇条書きの多さが主な原因です。

直したあとは45点で、指摘は14件になりました。残りは、この記事が説明のために引用している「静かに壊れる」「時間を溶かす」の検出と、「AではなくB」の参考指摘、残した箇条書き（30.6%）です。引用や、環境・確認結果の列挙は、意図して残しています。

英単語の前後の空白は、これまでの記事では「Claude Code に」のように空けていました。yomiyasuは、これを不要な空白として直す規則です。この記事から、空白なしで統一しています。

まとめ

  • インストールは npx skills add nanaism/yomiyasu -a claude-code -y --copy の1コマンド。作業フォルダの .claude\skills に入る
  • 入れる前に確認した範囲では、スクリプトは標準ライブラリだけで、通信はなかった
  • Windowsでは、スクリプトの日本語が文字化けする。PYTHONUTF8=1 で直った
  • スキルは手順書で、書き直すのはClaude自身。呼ばずに手で直すと、結果が変わった
  • 約400字のAIらしい文章は、lintで71点から91点になった。diffで、意味の抜けを1か所見つけて直せた

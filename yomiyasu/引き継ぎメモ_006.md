## 実際に踏んだ失敗と回避策

- **前回記事のリンクを取り違えた**: 最初に NotebookLM の記事(n4e0dc391b650)を貼ったが、直前の記事は TradingView(nebd65a86ecfb)だった。記事一覧 API(`https://note.com/api/v2/creators/om10cg72/contents?kind=note&page=1&per_page=5`)で取り直して直した。
- **タイトルが本文欄に入った**: `find` で見つけた textarea(ref)をクリックして入力したところ、本文欄に入った。本文を Ctrl+A、Delete で空にし、タイトル欄を `read_page` で探し直して入力した。タイトル欄の ref は、`read_page` の「記事タイトル」を使う。
- **見出し画像の保存で座標がずれた**: ウィンドウの大きさが変わり、スクリーンショットが白くなった。座標は使わず、ref でボタンを押して保存できた。
- **記事の数値が古かった**: 「この記事にも使ってみた」の「57点・11件」は、節を書き足す前の値だった。測り直して「45点・14件」に直した。
- **「通信先は GitHub の URL だけ」は不正確だった**: README などに別の URL があった。「スクリプトに通信処理はなく、README などにあるのは外部サイトへのリンクだけ」に直した。
- **公開済み記事の更新が拒否された**: 「公開に進む」ボタンの操作が、権限の判定で拒否された。回避せず、ユーザーが手で更新した。
- **「更新した」のに反映されていなかったことがあった**: 公開ページと編集画面を確認したとき、修正した 4 文がどちらにも入っていなかった(2026-10-06 時点)。公開ページは、取得し直して確かめる。WebFetch は 15 分キャッシュされるので、Chrome で開き直して確認する。
- **文字化け**: 上記のとおり `PYTHONUTF8=1` で回避。
